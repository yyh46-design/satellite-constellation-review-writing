# 大型卫星星座综述算法主线精修规范

版本：v1.2。更新日期：2026-10-19，Asia/Shanghai。沿用v1.1的对象、条件与决定要求，补充本轮确认的引用叙述方式。

本规范起于v2.9中文稿中调度问题与算法关系呈现不足的问题，本轮结合v3.1整合稿更新，继续指导后续内容精修。采用问题驱动的叙述性综述定位，保留五章主结构、中文内容先行和 CJA 投稿样式目标。v1.1纳入作者本次明确提出的决策表述要求，适用于后续各章、摘要和图表说明。其他章节安排仍按实际讨论推进，不表示全部章节标题已经确认或全部修改已经完成。

## 1 核心定位

核心问题统一表述为：**大型卫星星座如何在任务、资源与时间约束下，完成多星任务分配、活动安排和资源配置，并在需求与运行状态变化后及时更新可执行计划？**

持续服务用于评价这些决定能否转化为实际业务结果。对地观测与通信提供两类主要应用场景；构型、部署、补给、在轨服务、安全和故障恢复，按其对可用卫星、资源、具体活动和计划更新条件的影响纳入。方法归纳同时关注规模负担、资源耦合和反馈时效。

综述应使读者能够回答：需要决定什么；受什么条件限制；可采用哪些求解和协调方法；不同方法在什么条件下有用；现有验证能够支持多大范围的结论。

当前工作题名为“大型卫星星座任务与资源调度综述：求解方法、多星协调与动态更新”。优化、规则、协调与学习按它们参与决策的具体作用展开；增加学习算法名称不能代替机制说明。后续调整题名时，仍需核对其与正文范围的一致性。

## 2 内容取舍

| 内容 | 精修后的职责 | 处理要求 |
| --- | --- | --- |
| 多星任务分配、活动排序与时间安排 | 主要决策问题 | 明确请求与卫星的分配关系；解释观测时间段的定义，分别交代开始时刻、持续时间、先后顺序和竞争资源 |
| 能源、存储、处理与通信资源配置 | 主要约束与决策问题 | 说明哪些资源固定、哪些可调，以及与任务选择的联系 |
| 动态请求、扰动与在线更新 | 主要运行问题 | 说明信息到达、更新时机、保留活动、修复范围和生效时间 |
| 观测和通信业务 | 方法解释与比较的场景 | 说明具体问题以后再展开专业技术细节；保留不同业务的指标定义 |
| 部署、构型、备星与维护 | 可用能力的形成条件及相关决策实例 | 与调度的联系不清时压缩篇幅；具有代表性求解机制时纳入相应方法段落 |
| 轨迹控制、安全与故障诊断 | 可执行条件、资源变化与更新触发 | 保留影响调度的输入输出和适用边界，避免展开与主线无关的控制推导 |
| 软件平台与工程案例 | 执行、验证和部署条件 | 说明实际完成的功能及其规模，不代替算法性能证据 |

“通信”首次出现时区分三种角色：通信业务的接入及资源调度；观测数据的传输交付；多星决策所需的信息交换。三者分别标注其业务目标、容量约束或协调开销，不能仅因都涉及传输而合并成同一问题。

不预设必须保留95项来源、7张表或4幅图。现有95项来源先作为重组基础；增删取决于论证需要，并记录稳定来源ID和新旧编号映射。不得为增加文献数量扩大无关内容。

## 3 分类维度必须分清

| 维度 | 回答的问题 | 可使用的标签 |
| --- | --- | --- |
| 决策问题 | 决定什么 | 任务分配、活动排序、资源配置、计划修复 |
| 模型表达 | 怎样表示目标与约束 | 整数或混合整数模型、约束规划、连续优化模型、随机或鲁棒模型等 |
| 求解机制 | 怎样找到方案 | 精确求解、松弛与分解、贪心、局部或元启发式搜索、学习辅助或策略生成 |
| 决策组织 | 谁掌握信息、计算和修改权限 | 集中式、分层、分布式；拍卖及协商机制 |
| 更新方式 | 什么时候、根据什么调整 | 批量、滚动、周期或事件触发、局部修复、较大范围重规划 |
| 业务与验证 | 在什么场景得到什么结果 | 观测、通信；理论、固定实例、动态仿真、软件或硬件、飞行案例 |

这些维度可以交叉。一篇研究可以同时采用整数模型、局部搜索、分布式组织和滚动更新。MILP是模型类别，具体使用的求解、界和最优性状态另行记录；强化学习的状态、动作、训练与约束处理也需分别说明。不得把所有标签放进一棵相互排斥的算法分类树。

| 章 | 必须回答的问题 | 建议内容 | 完成判据 |
| --- | --- | --- | --- |
| 1 引言 | 为什么需要这篇综述，具体综合什么问题 | 多星任务与资源决策困难；相近综述；本文范围、问题与选录方式 | 读者能说出研究对象、方法视角及与既有综述的联系 |
| 2 卫星星座中的调度问题与比较基础 | 具体对象、已知条件、待决定内容、目标与约束分别是什么 | 两类业务的共同要素与差异；任务和资源关系；信息、组织与更新维度；一个贯穿示例 | 读者无需先掌握通信路由术语，也能理解后文在求什么 |
| 3 求解方法与多星决策组织 | 不同方法怎样得到可执行安排 | 建模与优化求解；启发式搜索；学习及混合方法；跨星协调；动态更新 | 核心方法有机制解释、代表证据、可比差异及适用条件 |
| 4 大规模与动态运行下的方法比较 | 如何取舍、组合和验证这些方法 | 规模及成本；资源耦合；反馈与不确定性；执行和工程证据；可检验问题 | 形成有条件、有来源支撑的综合判断，区分文献结果与本文推论 |
| 5 结论 | 文献总体支持哪些认识、还存在什么局限 | 回答引言的问题，概括方法取舍及后续研究 | 每个主要结论可回指第3或4章的具体论证 |

第3章建议按以下层次试排，最终小标题根据证据矩阵调整：

1. 建模、优化与分解求解。
2. 启发式与元启发式搜索。
3. 学习方法及与优化搜索的结合。
4. 多星求解组织与分配协调。
5. 动态需求与不确定条件下的计划更新。

前三节主要解释求解机制，后两节讨论其跨星组织与时间更新，明确它们是不同维度。没有足够正文证据支撑的路线应收窄、合并或标注局限，不能靠补列算法名称完成章节。

从v2.9重组时采用以下迁移原则：能力形成内容压缩为条件说明，代表性求解方法按作用进入第3章；安全、故障和执行衔接进入第4章的条件变化与运行验证。v3.1已据此整合。后续迁移仍保留来源、模型条件和版本身份，避免复制后重复论证。

## 5 文献提取与核心方法说明

先利用现有阅读记录建立方法矩阵，再对支撑核心比较的来源定向补核。每篇核心方法论文按[方法说明卡模板](METHOD_CARD_TEMPLATE_CN.md)记录：

- 实际版本及原文定位，分别记录AI核读与作者人工核准状态。
- 业务场景、验证规模与规划时域。
- 输入信息、输出决定、目标和关键约束；逐项区分已给定条件与待求变量，明确候选时间段经过哪些筛选。
- 求解步骤及决定性的机制。
- 多星组织、信息交换和更新方式。
- 离线准备、训练、在线求解、协调及配置生效成本，原文未报告的字段明确记为未报告。
- 对照方案、结果指标和分母、重要发现及模型边界。

核心方法的正文说明应让读者看懂“输入—表示—选择或搜索—约束检查—输出”。可按此顺序解释，不要求每篇都配伪代码，也不把所有论文写成同等长度的独立小传。

一般来源按相近问题分组综述，代表来源保留必要的机制细节。背景来源只承担背景职责。缺少关键字段时，先查实际正文及已有记录；仍无材料则缩小其证据角色，不能据摘要补写算法步骤、实验对照或性能保证。

## 6 比较规则

每个核心方法小节尽量形成“共同问题—方法机制—代表证据—条件差异—归纳”的推进；段落可以分工完成这些内容，避免机械套用同一长句模板。

必须说明至少一项实质差异，例如候选表示、耦合变量、约束处理、信息需求、更新范围或计算成本。只有作者、年份、算法名称和提升比例的段落，需要补机制或压缩为背景。

同研究、同实例和同预算对照可按原文报告性能差异；跨研究比较主要归纳模型、信息、求解和验证条件。异质场景不绘统一性能排名，不直接拼接提升百分比。未取得可比数据时，可以比较需要检查的条件，不能据此给出普适选型定律。

大型星座的论证应区分成员数、单位成员任务量、候选连接、资源竞争范围、更新频度及协调信息量。多个因素同时变化的实验不能解释成纯粹的星数扩展规律。单星或少量成员研究可说明局部机制，不能自动证明大型星座可扩展性。

可行解、最优解、松弛界和超时分别记录。学习策略输出只有经过原方法规定的约束处理后，才能按其实际保证解释。求解时间与完整响应时间分别列出，重叠阶段不机械求和；未测量的协调和部署时间不能当作零。

## 7 证据与引用

继续采用现有稳定E编号和命题记录。新归纳应绑定具体来源及可复查位置；主张强度与实际读到的版本、范围一致。DOI一致只确认身份，不能证明读到正式全文。

原论文结果、原作者解释、本文综合和研究建议分别标识。下载、提取文字、AI定向核读、作者人工确认和正式版本差异关闭分别计状态。本轮规范制定不增加任何精读计数。

仅有摘要可用于其明确支持的方向性描述，并记清状态；详细算法、数值比较、约束缺失和保证条件需要实际正文。未见全文不能据此写“原研究未考虑某约束”。取不到材料时可换用已读来源、降低断言或撤下该论点。

现有六组版本差异及其他未关闭项沿用原记录，不因重组关闭。AI处理记录保持 `human_verified=false`，作者实际核准后再据实变更。核心证据是否足够按最终保留的命题判断，不要求先把所有候选论文全文找齐才能继续写作。

结构重排期间按E编号保持身份；正文顺序稳定后统一生成引用编号、首次引用顺序和新旧映射。检查漏引、孤立书目、重复身份、数字范围和图表引文。未做迁移时继续声明静态引用；采用Zotero等软件也不能替代命题与原文核对。

### 7.1 文献提及方式与引用位置

采用数字顺序编码引用。作者名加编号、内容陈述后标编号、方法名加编号和“文献加编号”可以配合使用，分别服务于不同叙述目的。

- 一般归纳以共同问题、方法或认识作主语，并在对应内容后标注来源。
- 代表论文的机制说明可以作者名或方法名引导，明确谁提出了什么、该方法怎样工作。
- 对照具体论文的模型、假设或实验时，可以使用“文献[编号]”；避免每段机械重复这一开头。
- 多项来源合并引用时，共同表述须由各项来源实际支持。不同分句依据不同来源时，编号分别紧跟相应分句。
- 连续介绍同一研究时，在指代清楚的条件下使用“该方法”“该模型”，不必每句重复作者姓名；来源变化或具体结果须清楚归属。
- 本文的定义、分类、综合和建议与原论文事实分开；综合判断仍应能回指其依据。
- 不规定各类句式的机械比例。减少逐篇罗列，以共同问题和实质差异组织段落。
- 中文审阅Markdown保留方括号便于追踪，CJA Word导出使用数字上标。文末按全文首次引用顺序编号，引用合并、范围及稳定E编号同步核对。

## 8 摘要、引言与语言

摘要在第2至4章稳定后定稿，按“具体决策问题—综述范围和组织—主要综合认识—研究缺口”展开。开头说明任务分配、活动安排和资源配置；主体说明实际比较了哪些方法与维度；综合认识反映正文已建立的条件性结论。

接触可靠性、建链代价等具体例子可以支撑某条认识，其位置和篇幅应与全文作用相称。摘要不能只列算法类别，也不承诺正文尚未完成的系统比较。题名、摘要、引言贡献、章节和结论应描述同一范围。

### 8.1 具体对象、条件与决定必须明确

本条由作者本次讨论明确提出，作为后续写作和逐段精修的执行要求：

> 描述调度问题时，明确具体对象、已知条件和待决定的内容；专业术语首次出现时给出含义，避免让读者自行补全决策过程。读者读完一句话，应能说清楚卫星要做什么，以及调度需要作出什么选择。

1. **先写具体对象。** 优先使用卫星、观测请求、成像活动、地面站、用户、链路等有明确含义的对象。首次使用“成员”“活动”“能力”等概括词时，应说明具体指代；上下文已明确时可以简称。
2. **区分已知条件与待作出的决定。** 分别说明哪些信息由轨道计算、请求或已有计划给出，哪些变量需要调度选择。例如，在轨道给定的情形下，目标的几何可见时间段可以作为输入，执行观测的卫星、采用的时间段和成像开始时刻则可能是待决定内容。具体角色以所讨论模型为准。
3. **区分相关时间概念。** 时间窗口、开始时刻、持续时间和执行顺序分别表述。持续时间可能固定、离散可选或连续可调，不能未经原文核对就归为已知量；有些模型只选择预先枚举的观测机会，也不能替其增加连续开始时刻变量。
4. **说明窗口与可行性的边界。** “窗口”首次出现时说明它表示什么时间段。“可用”“可行”需说明已检查哪些条件，区分几何可见、经过部分约束筛选的候选机会与满足模型全部约束的安排。采用原论文术语时保留其定义，不把不同研究的窗口一律解释成同一种筛选结果。
5. **让动词对应实际操作。** 优先写“选择执行卫星”“选择观测时间段”“确定成像开始时刻”“分配下传容量”“撤销尚未执行的成像安排”。“实现活动配置”“形成能力协同”等表述只有在具体操作已交代后才可用于概括。
6. **按需要拆开压缩句。** 一句话同时包含对象定义、输入、决策和约束而难以读懂时，拆成相邻短句。具体信息可以由同段或紧邻表格共同交代，避免每句机械重复全部字段。

**改写示例（说明表达方式，所设条件不代表所有观测模型）：**

- 原表达：“从可用窗口中选择成像时刻。”
- 较清楚的表达：“已知卫星与目标之间满足几何可见条件的时间段，调度需要选择执行观测的卫星和观测时间段，并在成像时长给定的条件下确定开始时刻。所选安排还需检查姿态转换、载荷工作和资源约束。”

这里分别交代了几何可见时间段的含义、成像时长给定的示例条件、卫星与时间段的选择，以及开始时刻的确定。具体论文若预先给定开始时刻或联合优化持续时间，应按实际模型另写。

逐段精修采用[决策表述检查表](DECISION_CLARITY_CHECKLIST_CN.md)。核心方法卡、比较表和图注同时检查这些字段；不能通过修改措辞掩盖原文尚未核清的定义。

### 8.2 限制说明与全文语言

限制条件应紧邻相关结果，避免在方法尚未解释前连续堆叠审计式限定。内部下载进度、工作轮次和待办放入记录；影响解释的版本身份、验证规模及模型假设保留。不能为减少否定句而删去科学边界。

中文表达以作者能够理解和解释为准；减少重复自述、空泛贡献和机械转折，不用生僻同义词替换稳定术语。后续英文全文按中文科学定稿同步，不能将旧英文直接改版本号冒充已同步。

## 9 图表与期刊样式

正文内容先稳定，再调整图表。现有四图可分别支撑任务与资源关系、规模与减负机制、计划更新与执行时序、具体条件对照；需要补方法关系时先判断能否改现有图或表，不为固定图数保留内容。

图表应承担明确任务：问题图解释变量与约束关系；方法表比较机制和条件；运行图解释更新与生效；案例说明实际验证范围。不能从异质论文数值制作共同排名，不把示意时间线画成实测结果。

当前中文正文和英文绘图工作方式继续保留；可编辑标题使用黑色。PNG草稿的原始配色与AI来源记录保留，正式矢量重绘时统一字号、线宽、箭头语义和颜色。工具披露按实际制作方式及正式投稿时适用的期刊政策处理。

CJA是既定目标。具体字数、摘要长度、栏式、字体、分辨率和参考格式以可核验的官方要求为依据；本规范没有重新核查最新指南，不把本文自己的篇章建议写成期刊硬性要求。

## 10 执行顺序与交付

采用“全篇定向—代表段落试修—按章落实—全篇回查”。原四批任务划分见[v1.0执行计划](../algorithm_refinement_20261019/EXECUTION_PLAN_CN.md)，其进度描述保留为制定时的历史快照；v1.1及v1.2要求应用于后续各批及回查。

第一批先建立决策问题与方法矩阵，写清第2章基础，并试修第3章一个代表小节。第二批依据矩阵重组第3章和方法比较表。第三批完成第4章综合比较，并迁移、压缩能力维持、安全及执行背景。第四批回修引言、摘要、结论和图表，再做中文全文与Word检查。英文全文及投稿终核在中文科学内容稳定后另行安排。

正文发生修改的每批交付完整可读中文稿、修改前后对照、证据变化和未关闭项。阶段进度按问题是否讲清、比较是否建立和证据是否支持判断，不按改了多少段、读了多少篇或删了多少字判断。

## 11 验收标准

| 检查 | 通过时应看到的结果 |
| --- | --- |
| 摘要可理解 | 读者能指出决策对象、主要困难、方法组织及综合认识；不会仅据摘要误判为通信路由专题 |
| 问题可追踪 | 从一个请求可以说明输入、输出、目标、约束和更新触发；观测与通信的差异明确 |
| 决策表达明确 | 首次说明具体对象、已知条件和待决定内容；读者能说出卫星要做什么、调度选择什么 |
| 术语边界明确 | 窗口和可行性说明已检查的条件；开始时刻、持续时间与执行顺序分别交代 |
| 分类不混层 | 决策问题、模型、算法、组织和更新方式分别定义，交叉关系明确 |
| 方法有机制 | 核心方法说明怎样产生或修改方案，名称与性能数字不是唯一内容 |
| 比较有依据 | 关键综合认识对应代表研究及条件；跨研究结构比较与同研究性能对照分开 |
| 大型有含义 | 方法分析明确候选、任务负载、竞争或更新负担；小规模证据未越界外推 |
| 智能有职责 | 说明预测、搜索辅助、动作生成及约束检查的实际位置，没有只凭算法名称判断智能水平 |
| 证据可复查 | 核心命题具有实际版本和定位；AI核读与人工确认分开，未关闭项可见 |
| 全文相互对应 | 题名、摘要、贡献、章节、图表和结论的范围一致，来源身份和数值无漂移 |
| 交付可阅读 | Word与正文一致，改动页实际渲染检查；引用和图表顺序正确，历史稿保持原状 |

若仅语言检查或自动检查通过，只能报告相应工作完成。科学终核、作者确认、英文完成和投稿就绪分别报告。本规范本身不授予正式投稿、对外发信、推送或合并权限。
